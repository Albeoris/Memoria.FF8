# Selected FF8 field renderer

Wide camera clamping recalculates each background layer's camera contribution using its native horizontal scale, supplied through `backgroundLayerScales` or the native wrap currents. Layers retain their independent scripted displacement. Presentation samples retain their own scales before interpolation; camera shake is added after clamping.

`FieldRenderer(FieldAssets, outputWidth, outputHeight, modelTextureSampling)` returns a reusable RGBA framebuffer. The original logical canvas is 320×240. Wide ordinary-field targets expose horizontal continuation within the selected INF camera's image bounds, retaining the original vertical scale and camera tracking. Areas beyond those bounds stay black even when parallax tiles extend farther. The central viewport retains its native culling and depth ordering; separately clipped side strips admit additional tiles and periodic parallax copies. Models, effects and fades use the same image clip. Portrait targets, native movie viewports and fields without camera metadata retain the fitted original canvas. Geometry is rasterized directly at the requested resolution; model camera depth stays in world units regardless of output scale. Model filtering defaults to `ModelTextureSampling.Bilinear`; `Nearest` is available for original texel inspection. Bilinear RGB treats integer source UVs as texel centers, excludes transparent neighbors and preserves the nearest source cutout coverage. This smoothing convention prevents neighboring atlas regions from bleeding into mirrored model seams; it is a presentation enhancement. Original background tiles retain nearest sampling.

`ActorVisual` receives actual Events XYZ plus world-space DOFFSET once, FF8 Direction units, animation/frame, visibility and independent `PolygonColor` RGB (128 neutral). Visible primitive geometry requires explicit RGB bytes; there is no scalar shade or neutral fallback. Native SHADELEVEL controls ground-shadow packets, so the host never passes it as avatar tint. Executed SHADESET supplies the uniform native radius601..608, exact level609 and separate body center to the subtractive ground fan; unknown required authority refuses and default-radius shadows remain deferred. Rendering converts facing through the native `(DIR + 64)` convention. Background states select the installed MAP animation states. Optional background RGB modulation uses 128 as neutral; Events owns fade scheduling.

Optional `RootTranslationZ` corresponds to the separate SETROOTTRANS elevation word (native instance +98), default0. The SETGETA byte (instance +97) is not an elevation and must never be passed as this value. Original model textures come from selected installed PC archive members;128×128 source TIM textures are not HD replacements.

Background tiles are sorted and their nearest source sampling runs are calculated once for the selected output dimensions. Each run shades one source texel and fills its output spans; blend modes still combine with the existing destination pixels and transparent texels preserve both color and depth. States, module visibility and shades are read on every render, as are the source pixels. Projected vertex storage and the framebuffer are reused. This changes CPU work without reducing resolution, filtering or precision.

Verified: selected installed field data, layered/animated tiles, texture transparency, skeletal hierarchy and compound rotations, camera/entity/root transforms, foreground depth units, declared control bones, classroom root placement, filtered model cutouts and arbitrary-aspect output. Sixteen Assets test cases include captured native matrix, depth-unit and scalar background sampling/blending regressions at integral, fractional, clipped and portrait output sizes.

Remaining fidelity limits: integer animation-frame sampling (native interpolation deferred), simplified per-pixel depth rasterization instead of native primitive ordering, no eye-blink VRAM updates, no face-specific PSX semi-transparency/bias, and no native validation of BGSHADE timing. Original DirectMusic SGT/DLS field music and sound effects are outside this renderer. Original images are read locally and are not distributed with source.

## Live GPU rendering and software diagnostics

The Windows host renders battle ordering tables, component battle meshes, field tiles/actors/particles, world geometry/sky/fog and movie masks through the Direct3D GPU triangle backend. Shared scene code prepares the same ordered primitives for both backends. The live host renders directly into GPU targets; it uploads source textures and decoded video frames, without uploading a software scene framebuffer or reading GPU pixels back each frame. Consecutive primitives with the same material are batched while preserving submission order. Point-sampled field atlas quads carry their screen and source texel rectangles in the vertex stream; the shader selects a local source pixel before adding the atlas offset, keeping scrolling independent of atlas UV interpolation precision.

Normal launches use GPU rendering in Debug and Release, including controlled launches. Pass `--software-renderer` explicitly to use the CPU rasterizer in a live diagnostic session. The `scene-renderer` startup log and `SceneRenderer` control status identify the selected backend. Headless previews and tests without a graphics device continue to use the deterministic CPU renderer. Unsupported contracts fail with their original errors; the live host does not silently select a software backend.

Depth tests, alpha cutouts, texture windows, per-pixel perspective UVs, ordering and blend equations are retained by the GPU material stream. Hardware depth precision, sampling boundaries and color conversion can differ from the CPU reference by small rounding amounts. GPU regression tests use a hidden real graphics device and exercise blends, depth, field/movie composition and world/battle comparisons.

The application embeds `src/Memoria.FF8.App/Shaders/Triangles.mgfxo`; ordinary builds do not require a shader compiler. After editing `Triangles.fx`, regenerate it from the product root with the pinned tool:

```powershell
dotnet tool restore
dotnet tool run mgfxc src/Memoria.FF8.App/Shaders/Triangles.fx src/Memoria.FF8.App/Shaders/Triangles.mgfxo /Profile:DirectX_11
```

Run hardware checks on Windows with `dotnet run --project tests/Memoria.FF8.App.Tests -c Release -- --filter-class '*Gpu*'`. Installed-resource checks require `MEMORIA_FF8_GAME_DIR`; an optional standalone battle comparison additionally reads `MEMORIA_FF8_BATTLE_PERFORMANCE_SNAPSHOT`. Neither switch changes the saved simulation schema.
