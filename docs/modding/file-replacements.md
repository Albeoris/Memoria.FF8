# Junction file replacement packages

Junction packages provide static resource replacements and explicitly reviewed engine behaviors for Classic game data. The application connects movie/CAM playback, external music, field dialogue voices and the native texture layouts described in [Texture mods](texture-mods.md). An importer accepting an address does not establish that every asset reader consumes that overlay.

Place a standalone `.iroj` or unpacked package directory under `Mods/Junction` in the selected game directory or beside `Memoria.Launcher.exe`. Direct application starts can select a mod root with `--mods-dir <directory>`; its `Junction` subdirectory is used. Without that option, the application uses its adjacent `Mods` directory. Both roots use the [shared mod policy, ordering and reload lifecycle](texture-mods.md). The game-directory copy wins duplicate package IDs. Archives need no manual extraction; installed game files are not overwritten. A download wrapper directory may contain one or more `.iroj` files directly inside it, alongside readme or download metadata files. Each archive is discovered as an independent package, identified by its relative path under `Junction`. A directory with its own root `mod.xml` remains an unpacked package; archives inside it are not discovered separately.

## Manifest and configuration

The importer reads IROS versions 1.0–1.2 with uncompressed, LZS and LZMA entries. It parses root `mod.xml`, selects static `ModFolder` mappings using declared `ConfigOption` defaults, and publishes case-insensitive resource addresses. Comparisons against undeclared static options evaluate false, matching Junction. Selected wrapper directories are stripped while resource roots such as `data/movies`, `music` and `mods/textures` retain their meaning. `movies/` and `lang-en/movies/` remain distinct. Metadata, previews and readme files are excluded unless a preview is also a selected functional resource.

The Mods menu enables or disables the whole package. Archive settings live in `<archive>.iroj.ini`; directory packages use `mod.ini`. Global policy lives in `mods.ini` under the selected mod root.

Static manifest options use their declared defaults. Override a declared option in the package settings with `option.<ID> = <integer>`, for example `option.texture_variant = 2` when that ID and value are declared by its manifest. Bool options accept 0 or 1; List options accept their declared values. Unknown IDs, invalid values and malformed overrides fail the owning package. Changes are reconciled through the normal watcher or Refresh; no archive or manifest edits are needed.

Manifest `Compatibility/Setting` constraints may conditionally require or forbid declared option values in another active package. Missing or disabled targets and removed target options are ignored. A conflict reports the declaring package and prevents its files from contributing; select compatible options explicitly rather than relying on automatic setting changes.

Manifest GUID requirements and `Before` / `After` relationships determine package order. Missing or disabled requirements and ordering cycles produce diagnostics and prevent affected packages from contributing resources. `Compatibility/Forbid` with a `ModID` rejects the declaring package when that target is active; disable one of the conflicting packages. Conflicts are evaluated together, so mutual declarations do not depend on discovery order. Version-qualified relationships remain unsupported. The first matching contribution in package order wins.

Declarative `FFNxConfig` settings `enable_ffmpeg_videos`, `ffmpeg_video_ext` and `use_external_music` are understood. FFmpeg video decoding is enabled by default. Omitting `enable_ffmpeg_videos` or setting it to `1`/`true` produces no warning; an active `0`/`false` setting produces a warning because disabling FFmpeg is unsupported and decoding remains enabled. A configured video extension lets the original movie address select an MP4 or other replacement container without renaming installed resources. The presentation hints `ff8_use_gamepad_icons`, `enable_bilinear` and nonnegative integer `internal_resolution_scale` are validated and retained with diagnostics, but do not override this engine's renderer, input presentation or user preferences. Equivalent active declarations coalesce; conflicting values are rejected. Other FFNx settings fail import, including in disabled packages. HEXT is accepted only when its exact SHA-256 bytes and `hext/ff8/en_nv` target profile have been individually reviewed and approved for a specific engine behavior. The reviewed startup behaviors independently skip the publisher movie, Squaresoft logo, initial credits pause or credits images, following their manifest folder selections. Immediate manual credits skipping is always provided by the engine; a reviewed payload describing it is informational and its original toggle has no effect. HEXT is never executed, interpreted or published as a replacement file. Every HEXT payload is validated even in unselected folders; unknown or modified payloads require separate review and human approval before support can be added. Executable/library/plugin/helper declarations, executable payloads, dynamic game-variable conditions and unsupported manifest behavior also fail import. Rejected packages show `Reload failed`, contribute no files and leave unrelated packages available. Package code is never executed.

## Registered opaque resources

Registered `.tdw` files can replace ordinary archive resources even though the current renderer does not consume their font data. A root file such as `sysfnt.tdw`, optionally under `direct/`, addresses `main/sysfnt.tdw`; explicit `main/` and `menu/` paths remain distinct. The installed source must provide the corresponding key and format. Bytes are frozen through the resource service under normal priority and acquired-resource restart rules. A successful publication reports owning-package `resource-unused`; this is not a font-rendering implementation. Unregistered formats are not accepted as executable code or arbitrary runtime plugins.

## Native data files

The file replacement layer also registers `main/kernel.bin`, `main/namedic.bin`, `battle/c0mNNN.dat`, `menu/mngrp.bin`, `menu/mngrphd.bin` and native `world/wmsetXX.obj` resources. Root `kernel.bin` and `namedic.bin` names retain their main-archive identity; `world/dat/wmsetXX.obj` retains its world-archive identity. The optional `direct/` prefix has the same meaning as for model files. CSV exports are auxiliary material. Unregistered nested paths do not become aliases for canonical archive files.

Preparation validates all winning files against one candidate resource publication. Enemy ability and text references therefore use the selected kernel. Native two-section and eleven-section enemy layouts remain distinct. Kernel directory and record bounds, message terminators, menu indexes and world records are checked through their typed readers. A malformed winning binary rejects the update with owning-package diagnostics and preserves the preceding generation.

Native `Term` controls resolve through the selected counted `namedic.bin` dictionary and the resource abstraction. The native parameter-to-index calculation is retained; an index outside that dictionary contributes no text. Native text formatting requires a term source when such a control is reached. Authored interface localization remains a presentation layer over the selected source strings.

The menu index and data files form a compound contribution. When another package overlaps a contributed member, the lower-priority contribution loses as a whole; disjoint partial contributions can combine and must pass joint validation. This follows file replacement priority and does not turn the package into a native Field mod. Field components retain their separate grouping rules below, followed by incremental presentation patches.

Native menu TEX and compressed disc images are decoded and validated as registered file resources. Tutorial and magazine artwork consumes selected TEX bytes through the resource service. Images without a consumer in the current interface are published with owning `resource-unused` diagnostics; accepting those bytes does not add disc prompts, title layouts or font rendering. Binary files remain subject to the acquired-resource restart guard.

## Encoded model resources

Selected `direct/field/model/main_chr/<name>.mch` or `field/model/main_chr/<name>.mch` files replace installed main-character library resources through the shared resource service. Both layouts address the same resource and follow normal package priority. Names follow the native letter-plus-three-digits convention. Geometry and embedded TIM materials are validated before publication; a malformed winning contribution rejects the update rather than selecting a lower-priority file. Original field ONE resources continue to own placement and animation data, and native registration captures the selected MCH bytes.

Classic player body resources at `battle/d<hex character>c<three digits>.dat`, optionally prefixed with `direct/`, use the same publication mechanism. The current model decoder validates the replacement against the installed DAT section layout. Geometry, embedded textures, animations and native staging read the selected resource through the shared service. Executable file-selection tables remain authoritative. Texture target inspection uses the candidate resource, so its material member counts agree with the model that will be loaded.

Encoded resources remain fixed once acquired by a consumer. Changing or disabling an encoded replacement after acquisition reports that a game restart is required and preserves the current publication. Restart the game to apply the new selection. Texture-only replacements retain their normal live reload lifecycle. This preserves agreement between decoded models, materials, scripts and retained native registration.

## Encoded Field components

Ordinary Junction file replacements at `field/mapdata/<prefix>/<field>/<member>`, optionally preceded by `direct/`, address the installed `field/<field>/<member>` resources. The prefix is the first two characters of the field name. Recognized members are `chara.one` and field-named `.ca`, `.id`, `.inf`, `.jsm`, `.map`, `.mim`, `.mrt`, `.msd`, `.msk`, `.pcb`, `.pmd`, `.rat` and `.sfx` files. `.sym` files are authoring metadata and do not contribute runtime resources. Runtime-looking loose filenames that do not match the native member name produce `Junction.UnusedFieldMember`; language suffixes are not automatically aliased to the field basename.

For each field, all runtime members contributed by one package form an indivisible group. Groups are considered in effective package order. A group is accepted only when none of its member addresses intersects an already accepted group. An overlapping group is skipped completely, with an owning-package diagnostic; its nonoverlapping members do not survive separately. Rejected groups do not reserve addresses. Groups containing disjoint members may combine, and missing members use installed resources.

For example, groups containing `JSM + MSD`, `JSM + INF` and `JSM + INF + MSD` compete as whole groups. A fourth group containing only `RAT` can combine with whichever group wins. Selection is independent for different fields.

The selected snapshot is validated before publication, including script structure and opcode availability, statically provable message references against its selected MSD table, information/encounter records and native loader layout. Runtime-dependent message identifiers retain runtime bounds checks and produce a diagnostic explaining that they cannot be proved statically. Native ownership, dynamic operands and stack effects outside the bounded static analysis remain runtime checks; successful preflight does not establish that every story path has been played. An invalid or unsupported selected Field group is omitted completely, including accepted disjoint contributions to that field, with owning-package diagnostics. The installed field resources remain active; lower-priority conflicting groups are not retried. Other fields and package resources can still publish. Container decoding errors retain their existing transaction boundary. If the field was already acquired, the restart guard preserves the current publication until restart.

These remain Junction file replacement packages. The separate native Fields-format scene patches, including Depixelation, are prepared against the selected resources and applied afterward as incremental presentation changes; they do not enter file-group conflict resolution. Already acquired encoded components require a restart before their selection can change.

### Complete Field archives

A same-package triple at `field/mapdata/<prefix>/<field>.fi`, `.fl` and `.fs`, optionally preceded by `direct/`, replaces a complete field archive. All three files are required from the selected package. The shared archive decoder validates directory ownership, duplicate canonical names, FI bounds and zero-filled preallocation, compression frames and complete decoded lengths before publication. Listing paths are native archive labels; they are never extraction destinations.

Both the archive triple and every decoded member are frozen and published through the resource service. Archive members participate in the same field contribution group as loose files from that package, and conflict with loose members or archives from other packages by their canonical addresses. Within one package, the first canonical contribution in effective catalog order wins. A newly supplied archive may provide storage for an existing maplist field that has no installed archive; adding new maplist IDs is outside this mechanism.

An accepted archive owns its complete resource namespace. An absent member is unavailable and cannot be borrowed from installed data. Explicit members from an accepted disjoint contribution can still fill an omitted address. This keeps archive directory readers, decoded asset consumers and native allocation inputs on the same selected snapshot. Changes to acquired resource availability also require restart.

If PCB color corrections are absent, the engine preserves the models' own palette words and reports `Junction.MissingFieldColors` for the owning package. Absence is explicit in native registration state and contributes no fabricated PCB bytes or allocation length. This deterministic engine policy replaces the original executable's undefined reads of untouched memory after a missing PCB. A present malformed PCB remains an error.

Packages may include ancillary original saves, which are not automatically installed or loaded. The original-save importer can initialize a separately named engine snapshot against the selected mods with `--import-save <source> --output <new-snapshot> --game-dir <game> --mods-dir <mods>`. The same resource selection is needed when resuming that snapshot.

An incompatible or unreadable texture replacement is rejected individually. That consumer retains its source texture, other valid replacements publish normally, and the owning package remains active with a resource diagnostic identifying the file and reason. The same rule applies during live reload; rejected candidates do not fall through to a lower-priority package. Refresh revalidates the resources, so fixing the file clears its rejection when the new publication succeeds. Native model, manifest and reviewed-behavior validation retain their existing transaction boundaries.

## Reviewed startup behavior

Reviewed startup selections are read when the application starts and remain fixed for that presentation. Publisher skipping removes both segments of the startup movie; Squaresoft skipping also applies when the credits cycle repeats. Removing the initial credits pause preserves its first service frame and subsequent image timing. Skipping credits images also skips Overture, while normal title music remains available. New Game and gameplay movies are separate. Instant manual skipping has no engine option or off switch: an exclusively associated source option is omitted from exposed settings, and legacy values cannot disable it. Other declared static options remain configurable through `option.<ID>` in the package's settings file.

## External music

Selected `music/<track>.ogg` resources replace the corresponding native track. The track name comes from the native filename after its first hyphen, without the extension. Missing replacements retain native playback. Native track identities, slots, volume changes, pauses and stop operations remain authoritative.

An optional `music/config.toml` supports global `volume` (0–100) and per-track `offset_seconds`, `intro_seconds` and `no_intro_track`. For a no-intro request, an alternate track takes precedence over the intro offset. Ogg Vorbis loop comments define the loop region. Invalid configuration fails the affected package with a diagnostic. Package changes apply when the next track starts; an already playing track retains its resources.

## Field dialogue voices

Field voice packs use `voice/<field>/<clip>.ogg`. Playback resolves the window-specific `<field>/w<window>_<message><letter>` name, then `<field>/<message><letter>`. On the first authored page only, it then tries the window-specific and generic names without a letter. Page letters start at `a` and saturate at `z`; the source binding truncates window, message, page and choice identifiers to bytes. Choices use `<field>/<message>_<native-choice-line>` without rebasing the line number. Visual wrapping and font changes do not create new voice pages. Missing clips leave existing playback alone; closing a window, replacing a dialogue or leaving the field cancels its voice slot.

`voice/config.toml` supports integer `volume` percentages, single-file `shuffle` or `sequential` redirects and `gm-<story-value>` overrides. Section names use a hyphen in place of the field/name slash, as in `[scene-3a]` or `[scene-3a.gm-100]`. Redirects remain within the selected package and a missing redirect falls back to the requested file. Invalid configuration and unsupported reserved namespaces produce diagnostics. Default extensions are OGG; WAV files and editor sidecars are not automatically selected. Voice files supplied by a package whose own Field contribution was skipped do not bind to an unrelated replacement or installed script.

Voice payloads are copied and hashed into immutable disk snapshots through the shared resource service without retaining the whole voice pack in memory. Changes to acquired clips require restart. The Audio settings provide independent voice volume. Playback pauses with the presentation and restarts an open restored dialogue from its first presented page; sample phase and device handles are transient. Successful completion can request the ordinary confirm action for a single normal message, never select a choice or advance on a missing/failed clip. Multiple-window and native confirmability checks remain authoritative. With audio disabled, dialogue remains manually controlled. Music ducking is not enabled by default and voice playback does not change native music state.

## Indexed text tables

Selected `exe/<table>.msd` files, optionally prefixed with `direct/`, provide indexed text tables under the resource address `text/exe/<table>`. The current card-name consumers use `card_names`, which must contain all 110 native card identities in order. Parsing and texture preparation complete before the resource generation is published; malformed text retains the preceding generation and reports the owning package. Native speed controls remain nonvisual tokens; parameter zero terminates the text at its native boundary.

`battle_scans` contains 160 model-indexed descriptions. `draw_point` contains nine indexed rows, of which native interactions currently use the first eight. Scan and draw-point resource materializations refresh with the publication generation while already captured definitions remain immutable. A pending draw-point snapshot retains its selected message-bank hash; restoring it requires the compatible bank or an explicit migration. `card_texts` has 29 rows and is retained with an unused-resource diagnostic because the current card interface uses semantic localization rather than this native table.

Inventory, refinement, reward UI and Triple Triad look up card names through the current resource generation. A native battle definition keeps the names captured when that battle was constructed; subsequent battles use the new generation. Disabling a text replacement restores the original names.

## Movie lifetime and timing

Flat native movie filenames at a package root can replace the corresponding requested movie. Exact directory-qualified addresses take precedence within a package; distinct source directories are not merged. A camera companion is selected only from the winning video package, otherwise the original timeline is retained.

Uncompressed archive videos are read directly from their bounded byte range through FFmpeg's seekable `subfile` input, without extracting the movie or copying it into memory. Compressed entries, folder replacements and small CAM files are materialized only when selected. Playback pins its video and CAM together; package toggles apply to the next playback. Cached files remain available for the host's lifetime. Archive versions are checked before reopening a bound movie; changing its underlying archive requires preparing playback again.

Replacement video preparation reads container metadata without scanning or decoding the entire clip to count frames. The decoder detects the actual container, dimensions and frame rate instead of trusting the extension, and presentation follows actual decoded images and end of stream. The original installed movie retains exact decoded-frame counting for script callbacks.

Presentation frames and original movie callbacks use separate clocks. Replacement video and interpolated cameras follow detected replacement-media timing. Scripts, timers, original CAM receipts, saved frame indices and skip retain the original installed movie's timing. Replacement CAM flags must preserve the original script contract. Actor poses retain their existing update cadence. Additional actor interpolation, arbitrarily retimed videos and variable-frame-rate authoring remain outside the implemented contract.

For a replaced movie, its presentation CAM comes from the selected video's package. A video-only package retains the original camera; a lower-priority video's interpolated CAM is not combined with it. Interpolated camera frames can change the view between original callbacks, while model visibility continues to follow the original callback that produced the current actor samples.
