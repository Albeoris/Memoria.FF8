# Battle loadout ownership

`GameState.BattleLoadouts` is an optional versioned durable extension. `BattleLoadoutOverrides.Characters` keys logical character identities, not physical native rows, party positions, models or actor allocation IDs. Dream sequences reuse physical rows; `Records[row].CharacterId` identifies the recipient while `MagicRecordId` retains the junction row. Native equipment bytes remain unchanged.

Weapon and Limit overrides are independent. A missing `WeaponId` resolves the current native weapon. A null `LimitFamilies` resolves current native family defaults; an empty array explicitly removes every family. Ordered arrays are duplicate-free. Reset removes the selected character's overrides and keeps native learning. Definitions may be shared; action state must remain actor-owned.

`BattleLoadoutDraft` detaches saved arrays and stages all operations. Swaps materialize both effective assignments before replacing either participant. Moves remove the source assignment and append only when absent at the destination. Same-character exchanges are no-ops. Drafts retain their opening session epoch, relevant native/loadout baseline and resource generation. `GameSession.ApplyBattleLoadoutDraft` checks those values and safe mutation boundaries, validates the complete replacement, then publishes one root update. It does not save, consume RNG, rewrite native progression or mutate battle actors. The app host additionally rejects live editing while FFVII is active, including FFVII battles, because the dormant FFVIII session cannot assess the other world's mutation boundary.

`BattleAssets.ResolveBattleLoadout` resolves equipment mechanics and ordered family definitions. Ordinary battle projection captures the effective profile before actors are constructed. Current-game menu statistics use the effective weapon record with the recipient's native stat/junction inputs. `InstalledBattlePractice.PreparePlayer` initializes missing native scenario metadata from selected original resources and calls `BattleAssets.ApplyBattleWeapon` for laboratory weapon changes. It recomputes native maximum HP and clamps the scenario's current HP to that maximum, preserving injury and KO. Explicit magic stocks remain isolated; native equipment bytes are never rewritten. Laboratory actor definitions and presets have no live session Apply callback.

Normal Memoria component documents capture and restore the optional extension. Old documents without it use native defaults; empty arrays survive serialization. Execution snapshots can read the same pure state. Original FFVIII export retains the native recorded equipment and default Limit assignments, with explicit separate consent to omit custom loadouts. UI and command-line conversion preserve the source Memoria state.

Presentation retains the recipient's body, costume and skin while resolving equipment from its selected style owner. Semantic rig mappings transfer authored motion to the recipient skeleton; selected model, weapon, costume and resource revision identify cached resources. Temporary Limit banks restore the actor's ordinary selected style after completion rather than replacing durable assignments.

Semantic joints use their authored anatomical bind frames; matching raw matrix columns does not establish matching mesh orientation. Horizontal motion preserves native world units independently of leg length and vertical floor calibration. Shared equipment vertices and source-owned oriented effect references convert between joint frames, while physical body rendering retains the recipient's frame. Paired cinematic props use decoded source-contact provenance and matching track ownership in the actual draw basis, preserving authored separation and release. These optional presentation fields do not change saved progression or make older component documents invalid.

Body-integrated gear and intrinsic hands use explicit `NativeBattleActorSurface` layers. For example, Rinoa's launcher housing travels with her weapon style, while Zell's intrinsic gloves can coexist with that housing. Native recipients retain their original surfaces without duplication; foreign equipment and FreeHands remove separable old gear while preserving sleeves and skin. Combine can request its authored temporary launcher dependency. Each surface kind has a stable geometry identity, its own texture/material namespace and complete posed-model metadata, so collection ordering cannot exchange materials or split shared-vertex interpolation. Old saves reconstruct these nonprogress bindings from selected resources.

Composition preserves the selected resource provider's geometry, including Remastered meshes. This does not supply missing edition-specific battle-effect contracts: the current Remastered provider rejects the `runtime/native-executable` resource required by several existing effect readers. Installed Classic battle validation and Remastered composition validation are separate checks.

Focused tests include `BattleLoadoutDraftTests`, the optional extension case in `GameplaySaveComponentTests`, `BattleLoadoutEditorTests`, `BattleLoadoutResolutionTests`, `NativePcSaveBattleLoadoutTests`, `BattleLoadoutAnatomicalBasisTests`, `BattleSharedEquipmentFrameTests` and `NativeBattleCinematicPropContactTests`. `InstalledWeaponLoadoutBattleTests` uses the optional external fixture catalog entry `weapon-limit-field-source`, requires an existing standalone field save, and checks ordinary native attacks and subsequent encounter cleanup. Its bounded debug-victory cleanup is not evidence of natural victory or visual animation quality.
