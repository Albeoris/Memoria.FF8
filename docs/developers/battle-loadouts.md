# Battle loadout ownership

`GameState.BattleLoadouts` is an optional versioned durable extension. `BattleLoadoutOverrides.Characters` keys logical character identities, not physical native rows, party positions, models or actor allocation IDs. Dream sequences reuse physical rows; `Records[row].CharacterId` identifies the recipient while `MagicRecordId` retains the junction row. Native equipment bytes remain unchanged.

Weapon and Limit overrides are independent. A missing `WeaponId` resolves the current native weapon. A null `LimitFamilies` resolves current native family defaults; an empty array explicitly removes every family. Ordered arrays are duplicate-free. Reset removes the selected character's overrides and keeps native learning. Definitions may be shared; action state must remain actor-owned.

`BattleLoadoutDraft` detaches saved arrays and stages all operations. Swaps materialize both effective assignments before replacing either participant. Moves remove the source assignment and append only when absent at the destination. Same-character exchanges are no-ops. Drafts retain their opening session epoch, relevant native/loadout baseline and resource generation. `GameSession.ApplyBattleLoadoutDraft` checks those values and safe mutation boundaries, validates the complete replacement, then publishes one root update. It does not save, consume RNG, rewrite native progression or mutate battle actors.

`BattleAssets.ResolveBattleLoadout` resolves equipment mechanics and ordered family definitions. Ordinary battle projection captures the effective profile before actors are constructed. Current-game menu statistics use the effective weapon record with the recipient's native stat/junction inputs. `BattleAssets.ApplyBattleWeapon` supplies the laboratory equivalent for initialized native scenario actors; missing native inputs produce an explicit error rather than invented statistics. Laboratory actor definitions and presets have no live session Apply callback.

Normal Memoria component documents capture and restore the optional extension. Old documents without it use native defaults; empty arrays survive serialization. Execution snapshots can read the same pure state. Original FFVIII export retains the native recorded equipment and default Limit assignments, with explicit separate consent to omit custom loadouts. UI and command-line conversion preserve the source Memoria state.

Focused tests: `BattleLoadoutDraftTests`, the optional extension case in `GameplaySaveComponentTests`, `BattleLoadoutEditorTests`, `BattleLoadoutResolutionTests` and `NativePcSaveBattleLoadoutTests`. `InstalledWeaponLoadoutBattleTests` uses the optional external fixture catalog entry `weapon-limit-field-source`, requires an existing standalone field save, and checks ordinary native attacks and subsequent encounter cleanup. Its bounded debug-victory cleanup is not evidence of natural victory or visual animation quality.
