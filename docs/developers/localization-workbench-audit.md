# Translator-focused localization workbench audit

This audit follows text from canonical resource resolution to the renderer and the selected editing destination. Exporting a row is not evidence that its renderer supports selection, preview or live refresh. The review covers the authoring integration and its portable storage foundation; it does not establish original-game deployment or native visual parity. Integration fixes were in progress during the review. The findings below identify the observed defect and the required verification separately from existing coverage.

## Language and storage contracts

Source Scripts determine inventory, keys and native call contracts. Source Reference independently determines source-seeded prose. Target is the only writable translation string, including its leading presentation prefix. Reference ordering does not change those roles. Missing/null/empty Targets contribute no runtime override; explicit presence flags must also govern source materialization.

The Resources-only authoring assembly holds drafts, immutable concurrency evidence, editable conflict candidates, selective saved-change replay and user recovery state. Mods owns JSON/XLSX updates, complete row/dependency revisions, verified missing-row insertion and recoverable manifest/payload/sidecar publication. The host owns the selected destination, temporary overlays and live-generation publication. See [authoring contracts](localization-authoring.md).

The confirmed storage blockers are repaired: write-existing saves no longer reconstruct exports; source/reference and unknown metadata remain intact; workbook role cells are patched while ancillary parts survive; canonical revisions distinguish same-row edits from unrelated rows/formatting; new resource families update declarations and native metadata coherently. Twenty focused storage cases passed, and the broader localization selection passed 129 cases with one explicitly optional installed-resource skip. This does not replace final host/renderer verification.

The bounded fixes for A05 and A09 retain explicit input-instance provenance: tutorial renderers carry their parent binding to displayed segments, and `LocalizationTextComposition` carries `LocalizationTextFragment` spans through Concat/Join/Format. Identical wording from different resource keys stays distinct. Formatted parent templates keep their raw arguments rather than replacing Target with expanded player-specific text. The production picker must consume those fragment spans after layout/clipping; retaining metadata alone does not establish correct hit rectangles.

At the reviewed integration snapshot, source corrections for A01/A02, host conflict guards in A03 and the A04 history guard were visible. Their final host regression results were still pending. A06/A07/A08/A10 remained assigned integration work. A05/A09 provenance metadata and the concrete source compositions were verified as described below; final fragment picking was still separate work. This status distinction prevents the initial repro descriptions from being mistaken for a claim that all findings remain open or that all have passed end-to-end validation.

Five focused synthetic provenance/composition cases passed, together with 31 existing portable tutorial icon/document regressions. These checks establish retained canonical metadata through the repaired transformations. Fragment hit rectangles and host lifecycle outcomes require their separate integration checks before those portions are marked complete.

## Verification limits

Portable storage regression coverage includes complete row conflicts, explicit source roles, missing/null/empty Targets, unknown metadata, ancillary workbook parts, generic missing-family insertion, recoverable new-file transactions and independent replay. Renderer/host checks must additionally cover the final production draw and lifecycle paths; a passing exporter or parser test alone does not close a renderer finding.

This audit uses redistributable synthetic inputs and source inspection. Installed-resource coverage remains optional and explicitly configured. Native fonts, original window parity, encoding validation and original-game export/deployment are separate claims with their own evidence; none is inferred from this matrix.
