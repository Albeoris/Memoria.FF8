# Create GF ability mods in the game

[Documentation](../README.md) / Players

Open **Mods → Create Mods**. Under **GF Abilities**, choose **Create new mod**, **Edit existing GF mod** (enabled or disabled packages), or **Edit this playthrough**. Creating a mod opens an independent untitled draft immediately; its name and destination are chosen when saving. This gameplay tool supports Classic resources. The sixteen learnable GFs are available whether acquired or not; summon-only entities have no learning table.

The catalog occupies the left pane, with separate ability, AP cost and Present fields. Search has a visible caret, Clear button and category filter. Enter finishes text entry and focuses results without editing. Escape retains the query. Controller users can reach the complete catalog through categories and pages without entering text.

The GF pane displays one ordered collection in two columns, filled down the first column and then the second. Narrow layouts use one column. Each pane has a range and shared Previous/Next page controls. Left/Right and Page Up/Down move a full page while preserving the selected page slot; Up/Down visits each logical entry. The mouse wheel pages only the hovered list. Descriptions and current progress stay in bounded selection details; **Details** opens the full information.

Clicking a row selects it without editing. **Add** appends the catalog ability; **Replace** arms target selection. **Swap** pins a GF ability and lets you choose a second ability, including on another page. The operation banner names both participants; use its explicit button or Confirm to commit. Selection and paging alone never commit. Cancel returns to the initiating selection. Leaving target selection, changing GF or entering Preview cancels the operation.

**Start learned** checkboxes and the Card binding edit the template. Current learned state and AP are preserved unless explicitly applied in the apply review. Dirty rows have red text and an asterisk. Confirm on a dirty GF row undoes its latest relevant command, including both sides of a swap; pending replacement or swap takes priority. **Undo** remains available explicitly, and larger dependent groups require review. Saved contributions are clean; **Actions → Restore inherited value** authors a new change rather than inventing history from an earlier session.

Use the displayed CameraLeft/CameraRight bindings to focus catalog/GF, RotateLeft/RotateRight to select the GF, and Tab/Shift+Tab to traverse controls. Confirm belongs to the focused control. **Actions** uses the Menu binding and exposes document, selection, search and controller navigation commands. **Switch column** defaults to Ctrl+Tab or right-stick press and can be remapped. Changing editing target with unsaved changes offers Save/Apply, Discard or Cancel.

**Preview** opens a separate read-only workspace with **Source**, **This mod only** (or **These local changes only**) and **Current setup** modes. Current setup has one **Include selected layer** toggle; simulating a disabled package does not enable it. New candidates show their provisional position. Source identifies an opaque external baseline when applicable. **Back to editor** restores the editing GF, cursors, query and focus. Preview cannot save, apply, edit or undo, and never changes current progress.

**Apply changes** (playthrough target) or **Actions → Apply to this playthrough** (package target) reviews the selected contribution's structural changes, learning targets and junction consequences. Existing AP and learning are preserved. The optional **Also apply edited starting states** affects only starting states explicitly changed in this editing session; it shows exact learned/forgotten/AP changes before applying. These progression resets occur once. Applying a package draft keeps its unsaved state and session undo history until the package is saved or discarded. The contribution becomes save-local and its matching package GF document is excluded for this playthrough. Other payloads and global package enablement stay as configured. Save the game normally to retain the change.

**Save mod** updates only `gameplay/gf-abilities.json`; **Save as new mod** creates an independent document identity. The native folder picker creates the default `Mods/Memoria` directory if needed and opens there. Navigate freely to choose or create any package folder, including an external or nested folder. To use a package saved elsewhere, place it directly inside a discovered mod root such as `Mods/Memoria`. Other package files and settings are preserved. An externally changed file requires reloading or Save As. Saving a document and activating it are separate results: check **Installed Mods** for the current status and diagnostics. New packages follow automatic enablement policy. **GF changes review** accepts pending mod changes that affect current progression or junctions. Unsafe battle/tutorial/party-transition boundaries reject application with a reason.

New packages remain listed when activation is rejected. **Awaiting GF review** means that **GF changes review · Pending** has consequences to confirm; **Reload failed** means that the details contain the activation error. The previous runtime generation remains active until validation succeeds. You can disable or edit a listed package while its activation is blocked.

Applying locally and then exporting keeps local ownership. **Actions → Use package** explicitly reviews removal of that local contribution and reactivation of the saved, enabled GF document. Independent local contributions remain. Missing previously applied packages retain their saved GF payload; the target list offers explicit reviewed removal. Their unrelated missing model/texture files are not reconstructed.

Memoria saves preserve expanded lists and dormant progression. Original FFVIII saves cannot carry changed learning definitions or arbitrary display ordering, even when the list is small. The editor warns once when learning/effective capacity is exceeded. Original-format saving/copying uses a separate concrete loss review and a projected copy; cancellation preserves the full playthrough and destination. Unrelated unsupported gameplay settings can still require Memoria format.

If another tool changes compatibility fields, Memoria compares them with the last saved mapping. Clear learned/AP/forgotten changes are adopted by identity. Ambiguous structural changes retain an opaque baseline and recovery information; former native documents are held out of automatic replay. **Review recovered native GF layers** explicitly previews reactivation over that baseline. Historical changes already baked into it cannot be subtracted by disabling a former package.
